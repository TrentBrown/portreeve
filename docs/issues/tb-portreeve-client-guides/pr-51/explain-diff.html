  • Bridge-local credential custody

A technically valid receipt protects execution from evidence drift. It never replaces the human's current intent.

CLI guide

  • Service install, start, status, and logs
  • Port and claim evidence
  • Stack apply, prepare, resolve, and confirm
  • Launcher init, validate, trust, and start
  • Dry-run reclaim and pruning before execution

The CLI keeps full local administration authority, so unsafe eviction is documented as a separate last-resort escape hatch.

Support boundary

Desktop is macOS-only. Standalone CLI and MCP are supported on macOS and Linux. The JavaScript client uses its documented Node.js or Bun runtime and local Unix socket. Windows is unsupported. Ordinary Docker-backed listener evidence does not imply Docker Sandbox orchestration or integration.

Knowledge check

Why do MCP mutation recipes stop after preview?

The preview binds technical evidence, but only a human can affirm present intent for that specific proposed effect.

When is a lease confirmed?

Only after the service successfully binds and PortReeve can verify the actual process or Docker evidence.

What is the safest first troubleshooting step?

MCP begins with diagnostics; CLI begins with layered status. Both preserve evidence before mutation.

Does a stored PID prove ownership?

No. Fresh listener evidence and process lineage remain authoritative.
