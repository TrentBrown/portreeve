A safe file before a powerful command

This change establishes the configuration and trust foundations for PortReeve Launcher. It intentionally runs nothing.

BackgroundIntuitionCodeQuiz

Background

PortReeve already knows a stack's components, endpoints, allocated host ports, activations, and fresh listener evidence. A project launcher knows how that particular project starts and stops. The new Launcher feature will connect those authorities without moving arbitrary shell execution into the daemon.

Before a future CLI or Desktop button can execute a command, PortReeve needs an exact answer to four questions: is the file valid, does it still contain the reviewed bytes, does its working directory remain inside the stack, and are its endpoint mappings meaningful?

Intuition

Think of trust as a seal placed on bytes, not on a filename. If a developer changes whitespace, the semantics may be unchanged, but the reviewed artifact is no longer exact. The SHA-256 revision changes and execution must wait for another review.

{
  "version": 1,
  "operations": {
    "start": { "command": "npm run start" },
    "stop": { "command": "npm run stop" }
  }
}
Important boundary: this PR parses, validates, suggests, fingerprints, and stores trust. It adds no shell runner, daemon operation route, CLI launcher command, or Desktop IPC.

Command discovery is similarly conservative. One exact package script can be suggested. A package script and Make target for the same operation become two visible candidates, so PortReeve leaves the field blank instead of guessing.

Code walkthrough

1. Strict definition

definition.js describes fixed operations, shell choices, timeouts, attached-Start constraints, structured endpoint references, reserved environment names, and deterministic serialization.

2. Safe document

document.js resolves real paths, rejects symlink escapes, caps input, creates exclusively through a hard link, and replaces atomically only after the exact baseline is rechecked.

3. Low-friction suggestions

discovery.js reads only known files in one directory. It never executes a manifest and always returns provenance. Normalized environment-name collisions are refused.

4. Shared private state

local-state.js gives Desktop and CLI one mode-0600 state file inside PortReeve's marker-owned data root. Token-bound locks prevent an old writer from deleting a replacement lock; stale locks recover without trusting PIDs.
