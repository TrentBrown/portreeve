Background

The beginner's model

A port number is an address on one machine. PortReeve already assigns those addresses without collisions. A development stack, however, is a conversation among processes: a website must learn the API address, an API may need a Docker-published database address, and a launcher must start and stop them in the correct order.

Stack fileDeclares components and endpoints, never current assigned ports.
PortReeve daemonAllocates addresses and observes listeners.
Launcher fileMaps endpoints to environment names and trusted commands.
Project CLIOwns ordering, health, containers, and cleanup.

The design deliberately stops PortReeve short of becoming a general orchestrator. The daemon coordinates addresses and safe operation metadata. The user's trusted CLI or Desktop process executes project commands locally.

The narrow background for this PR

PRs #25 through #32 built the strict launcher document, daemon coordination, environment and evidence services, command execution, CLI, attached and verified modes, Electron boundary, and Launcher tab. The remaining risk was not missing code; it was an assembled feature whose public contract and platform claims had not yet been verified together.

Intuition

Think of the stack definition as a seating chart and the launcher definition as a set of labeled extension cords. PortReeve may move a service to another seat, but the cord label remains API_HTTP_PORT. Immediately before Start, PortReeve connects that label to the current allocation. The checked-in launcher never needs a new commit merely because the port changed.

1. Trust bytesportreeve.launcher.json hashes to one exact revision.
2. Resolve generationapi.http → 43127
3. Inject contextAPI_HTTP_PORT=43127
4. Compare evidenceCommand result is advisory; listeners or activation establish state.

This separation explains several safety choices. External edits invalidate trust. Stop runs the project's Stop command rather than killing whatever happens to listen. Verified activation requires a matching generation instead of exit zero. Attached Start can be terminated only through the exact process-group handle held by the application that created it.

Contract assertions

The release documentation test requires every major guide section, every reserved context variable, reset semantics, degraded refusal, no trust bypass, and canonical example bytes.

What the final slice intentionally does not change

daemon: no shell commands, no raw output, no credentials
launcher file: no assigned ports, no arbitrary secrets, no database IDs
Desktop renderer: no filesystem path authority, no process handles
first release: no PTY, detach, reattach, Windows runtime, or language generator
