PortReeve PR #61

Make an alpha release understandable before making it public

This slice connects deterministic release machinery to the two people who must reason about it: the prospective user and the release operator.

Background

The beginner's model

PortReeve has three independent labels. Alpha describes product maturity. Preview describes a distribution channel. Unsigned describes macOS trust evidence. None proves either of the others.

The release engine already records source, artifacts, native evidence, policy, and publication state. Before this PR, that precision was not presented consistently at the repository entrance, inside Desktop, or in the operator's normal invocation path.

Safety boundary: preparing a release candidate must never be interpreted as permission to publish it.

Intuition

Think of the release record as a sealed shipping manifest. Several surfaces may read and explain it, but only repository scripts may advance it.

A rehearsal uses publish=false. It proves the multi-platform candidate without entering the publication environment or mutating a tag, release, tap, update file, or npm package.

Code walkthrough

1. Persistent product truth

The README warning appears before the logo. The Desktop indicator lives inside the global application header, before primary navigation, so changing tabs cannot hide it.

2. Safe installation and removal

The installation guide covers Homebrew, architecture-specific DMGs, digest comparison, Apple's scoped Open Anyway workflow, explicit service setup, routine uninstall that preserves data, and a separate confirmed purge.

3. Generated distribution copy

The publication plan adds the alpha and trust warning to preview release notes. The generated cask caveat points to the same maintained guide and preserves service/data lifecycle separation.

4. One operator contract

docs/releasing.md is the durable runbook. The project-local skill reads it and invokes existing package scripts; it does not encode another state machine or grant itself publication authority.

bun run release:prepare -- --channel preview --version 0.1.0-preview.1
gh workflow run release.yml -f channel=preview -f version=0.1.0-preview.1 -f publish=false
