A release becomes a recorded progression

This first release-pipeline slice turns an implicit series of build commands into a strict, resumable preparation record. It deliberately stops before Desktop DMGs, hosted aggregation, or public publication.

Background

PortReeve already knew how to compile four standalone executables, pack its public JavaScript client, render a Homebrew formula, and verify a native lifecycle. The old entry point, scripts/release.js, did all of that work in one top-level script and wrote a build manifest under dist/release.

Before

A build directory answered “what files did this command emit?”

  • No ordered release state
  • No channel, maturity, or trust policy
  • No durable approval boundary
  • No safe interruption/resume contract

After this slice

A release record answers “what source and policy produced which exact bytes?”

  • Versioned schema and ordered stages
  • Independent release and component versions
  • Artifact sizes, digests, provenance, OS, and architecture
  • Exact-source recovery after interruption

The distinction matters because a build is not yet a release. Native checks, Desktop packaging, signing policy, Homebrew metadata, and human publication approval all occur later. A file’s presence cannot prove any of those facts.

Core intuition

Think of a release as an append-only passport. Each checkpoint stamps the passport only after inspecting the stamp before it. Skipping from source directly to publication is invalid even if plausible-looking files happen to exist.

Important: PR #57 implements the solid green preparation stages. The dashed stages remain deliberately unavailable. This is safer than exposing a nominal publish command backed by incomplete evidence.

One coordinated version, several component versions

A coordinated preview such as 0.1.0-preview.1 may contain server, Desktop, and client components that each still report 0.1.0. Download URLs use the coordinated GitHub tag; artifact names and installed formula version use the component version. That separation permits several previews without lying about the identity embedded in an executable.

Code walkthrough

1. The release record

scripts/release-record.js defines the schema and ordered stage list. Record creation validates semantic versions, source commit, component versions, tool versions, channel, maturity, and trust. Loading JSON repeats strict validation instead of trusting data merely because its schemaVersion equals one. 

{
  "releaseVersion": "0.1.0-preview.1",
  "versions": { "server": "0.1.0", "desktop": "0.1.0", "client": "0.1.0" },
  "policy": { "maturity": "alpha", "channel": "preview", "desktopTrust": "unsigned" },
  "stages": ["source-pinned", "policy-resolved", "native-cli-built"],
  "artifacts": [{ "filename": "portreeve-v0.1.0-macos-arm64", "sha256": "…" }]
}

Artifacts must live beneath the release workspace, have unique public filenames and paths, cite a completed provenance stage, and match their recorded length and SHA-256. Atomic temporary-file replacement prevents a reader from seeing half-written JSON.

2. A callable build stage

The old top-level build body moved to scripts/release-build.js as buildReleaseArtifacts(). The legacy release:build command is now a thin compatibility wrapper, so existing CI keeps working while the new orchestrator calls the same implementation.

3. Non-publishing preparation

scripts/prepare-release.js supplies the new Commander-based entry point:

bun run release:prepare -- \
  --channel preview \
  --version 0.1.0-preview.1

The command requires a clean checkout, records the exact commit and remote, writes the initial record before the expensive build, builds artifacts, records their independently computed identities, and emits a human-readable publication plan. It does not call GitHub, alter a tap, create a tag, or contact npm.

4. Bounded recovery

If the build stops after the initial record is written, --resume permits one precise recovery. The current checkout must still be clean and must match the original repository, commit, channel, maturity, and trust policy. Resume is refused after artifact state exists, preventing a successful version from being overwritten accidentally.

What remains

This is a cumulative feature. Later slices will merge native evidence from all four operating-system/architecture targets, package separate ARM64/x64 Desktop applications and DMGs, generate a cask, reorganize GitHub Actions, decouple npm, add the Alpha Preview user experience, write the runbook and skill, and finally rehearse publication with fake adapters. A real public release remains a separate human gate.
