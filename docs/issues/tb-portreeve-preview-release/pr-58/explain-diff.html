Background

A release build can inspect a macOS or Linux executable without running it. That proves the file format, but it does not prove that the executable starts, serves requests, or works with launchd or systemd. PortReeve ships four native targets, so one laptop cannot supply all required runtime evidence.

macOS ARM64Apple Silicon runner
macOS x64Intel runner
Linux ARM64ARM Linux runner
Linux x64x86-64 Linux runner

The previous slice already created a release record containing source identity and SHA-256 identities for the built artifacts. The missing question was how four independent runners could contribute proof without rebuilding or racing to edit the same JSON file.

Intuition

Build once
→
Promoted bytes
→
4 native fragments
→
Aggregate once

Each runner receives the same promoted artifact workspace. It verifies checksums and format, runs the matching executable, checks the manual server, and exercises the supervised lifecycle. Success produces a small create-once fragment.

{
  "releaseId": "portreeve-v0.1.0-preview.58.2",
  "target": { "operatingSystem": "macos", "architecture": "arm64" },
  "artifact": { "filename": "portreeve-v0.1.0-macos-arm64",
                "sha256": "aa9e9541..." },
  "checks": { "manualServer": true, "supervisedLifecycle": true }
}
The key invariant: evidence is about one source commit and one exact executable digest—not merely a successful job bearing a similar name.

The aggregator accepts exactly one fragment for each target, sorts them into canonical order, and advances the record only when the matrix is complete. A missing Linux runner leaves the release preparing; it does not produce a partial “verified” state.

Code walkthrough

1. A strict transport document

native-release-evidence.js defines creation, validation, create-once persistence, and deterministic aggregation. It rejects stale source commits, altered artifact identities, duplicate targets, missing targets, and attempts to aggregate twice.

2. One command per runner

release:native-evidence derives the target from the real host. It verifies the recorded artifact set both before and after native execution, then writes one fragment. It cannot be told to pretend that an ARM runner is x64.

3. One command at the join point

release:merge-native-evidence reads transported fragments and atomically updates the release record. It never invokes the compiler, so the verified bytes remain the promoted bytes.

4. Stronger loaded-record validation

The release-record validator now cross-checks every fragment against recorded artifacts. Once the native stage exists, the exact ordered four-target matrix must also exist; before that stage, fragments are forbidden.

5. Compatibility retained

The existing verifier still defaults to dist/release. An explicit PORTREEVE_RELEASE_DIRECTORY lets the new collector point it at a versioned prepared workspace.

Still pending: this Mac proved macOS ARM64. Hosted jobs must produce macOS x64 and both Linux fragments before aggregation can pass.
