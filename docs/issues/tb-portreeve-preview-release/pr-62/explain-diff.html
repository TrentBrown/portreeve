Background

The beginner's model

A release candidate is not a release. It is a sealed set of exact bytes plus evidence describing where they came from and what has verified them. Publication is a later, explicit decision.

PRs #57-#61 built the record, native artifacts, Desktop packages, distribution material, hosted workflow, alpha user experience, and operator documentation. PR #62 connects those pieces in a real hosted run.

Safety boundary: the rehearsal used publish=false. GitHub created temporary workflow artifacts, but it did not create a Git tag, GitHub Release, tap commit, update publication, or npm package.

Intuition

Think of this as a dress rehearsal performed with the theater doors locked. Every actor and prop must be present, but no audience is admitted until the director gives a separate signal.

Code walkthrough

1. A read-only candidate inspector

scripts/inspect-release-candidate.js validates a downloaded final record, every artifact digest, the publication-plan binding, complete native targets, both DMGs, and the no-public-mutation fact. It does not advance state.

bun run release:inspect --record /path/to/release-record.json

2. One hosted release engine

The manual workflow invokes the same repository scripts used locally. Prepare builds the initial workspace; matrix jobs add architecture-specific evidence; aggregation and Desktop finalization consume only recorded predecessors.

3. Operator guidance follows the evidence

The runbook and project skill now tell an operator to download the distribution artifact and run the inspector before considering publication. The command is also contract-tested so the documentation cannot quietly drift away from the executable interface.

4. Tampering and incomplete state fail closed

Tests prove that inspection refuses an incomplete candidate and a publication plan whose bytes no longer match the recorded SHA-256. Stable Desktop finalization independently refuses absent Apple trust evidence.
