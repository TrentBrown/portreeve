PortReeve gains the map that explains the territory

The desktop already coordinates ports, stacks, and project launchers. This change adds the missing orientation layer: a local Guide that explains where PortReeve's responsibility ends and the project's responsibility begins.

Background Intuition Code Quiz

Background

One address authority, many project tools

PortReeve is a per-user service. It maintains durable port identities, leases candidate ports, verifies listeners and Docker publications, and keeps a coherent allocation generation for a stack. Desktop, CLI, client library, and project launchers all reach the same private Unix-socket authority.

What it deliberately does not do is equally important. The project launcher still starts processes and containers, chooses dependency order, injects environment, manages secrets, checks application health, and shuts the stack down. Listener ownership proves who bound an address; it does not prove the application is ready.

The durable boundary: PortReeve coordinates addresses; project tools coordinate work.

Before this PR, that model lived across repository documentation and several operational screens. A user arriving in the desktop could operate the system without finding one concise explanation of it.

Intuition

A progression from convenience to native ownership

The Guide presents integration as an upgrade path rather than a binary choice. Each step keeps project commands authoritative while reducing the amount of PortReeve-specific scaffolding around them.

Code

A deliberately unprivileged renderer change

OverviewPortsStacksLaunchersGuide
  1. Markup: index.html pluralizes the collection tab and heading, adds Guide last, and supplies the orientation, three paths, semantic architecture figure, readiness warning, and six native disclosures.
  2. Navigation: renderer.js toggles the fifth section and hides the live runtime strip while Guide is active. The existing dirty Stacks and Launchers editor guards run before any tab activation, so Guide cannot bypass unsaved-change protection.
  3. Presentation: styles.css uses existing Fogbound Coast constants. At 900 pixels the integration cards and authority map become one column; at 820 pixels the interface row becomes two columns.
  4. Trust boundary: no package dependency, remote resource, IPC, preload, server, protocol, or database file changes. The Guide works when PortReeve is unavailable because its content ships with the app.
  5. Protection: the new focused test checks five-tab order, plural-versus-singular naming, required concepts, semantic structure, responsive rules, and the absence of embeds, renderer networking, and Mermaid.
