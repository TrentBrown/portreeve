Portreeve initial release

PR #1 turns an empty repository into a local, per-user port authority, its official JavaScript client, native lifecycle tooling, and a fail-closed release pipeline.

Runtime architecture

A foreground portreeve serve process owns a private Unix socket and SQLite registry. Clients negotiate protocol compatibility, acquire a short-lived candidate lease, bind their TCP listener, and confirm the run with fresh listener and process-lineage evidence.

Safety model

Inventory is derived from complete LISTEN-specific lsof snapshots. Normal reclamation signals only listeners verified against one confirmed run and revalidates every process instance before each signal. The any-owner escape hatch is a separate, explicitly unsafe, exact-port operation and still remains fingerprint-bound.

Developer and operator surface

Commander.js provides human and JSON CLI contracts for serving, lifecycle, ports, claims, configuration, logs, and history. Native integration uses per-user LaunchAgents on macOS and systemd --user on Linux while preserving foreground manual operation.

Distribution

The build emits four standalone executables, checksums, a manifest, a Homebrew formula referencing the same artifacts, and a dependency-free npm client tarball. Publication is gated on native target execution, matching tag/version metadata, and public repository visibility.

This remains a draft boundary. R1-R7 pass; R8 is open until a Linux ARM64 release runner, public repository visibility, and npm credentials are in place. Nothing has been published.
