Why this slice exists

PR #8 gave a worktree one immutable generation of allocated ports and one activation. That solved coordinated allocation, but a consumer still needed a safe answer to: “Which addresses may I use?” PR #9 supplies that answer while keeping project startup and Docker topology under launcher control.

The key inversion Portreeve publishes scoped address facts. A project launcher decides start order, supplies the sandbox gateway, writes the runtime file, and mounts it read-only. Portreeve does not become a general process orchestrator.

The mental model

Activationselects one generation
Componentsets the visibility scope

Readstrict sandbox document
Host publication

The generation's allocated loopback host and port.

Docker network

A nullable service name and container port from the checked-in definition.

Sandbox gateway

A launcher-supplied host token paired with the allocated host port.

These views are deliberately not collapsed. An allocated host port is not container evidence, and a gateway address is not listener ownership evidence.

Code tour

1. Strict public shapes

src/protocol/schemas.js introduces strict schemas for resolution, snapshots, and gateway input. Definitions now reject dependencies on unpublished endpoints because immutable generations contain only published addresses. 

{
  schemaVersion: 1,
  definitionRevision,
  generationId,
  activationId,
  component: "website",
  own: { http: { component, endpoint, host, dockerNetwork } },
  dependencies: { backend: { component, endpoint, host, dockerNetwork } }
}

2. One activation, one scope

src/stacks/discovery-service.js loads the activation, derives its generation, verifies the generation still matches the current definition, and maps only the consumer's published endpoints and declared aliases. Failed or ended activations cannot publish discovery.

3. Two socket operations

The server exposes POST .../resolve and POST .../snapshot. The official client preflights the independent stack-discovery-v1 capability before invoking either route, so an older daemon fails clearly instead of partially interpreting a new request.

4. A dependency-free runtime reader

packages/client/src/discovery.js writes through a private same-directory temporary file and atomic rename. Its reader accepts an explicit path or PORTREEVE_ENDPOINTS_FILE, caps input at 1 MiB, rejects unknown fields, and can require an expected revision, generation, activation, or component. 

const endpoints = await readEndpointSnapshot(undefined, {
  generationId: expectedGeneration,
  component: "website"
});

fetch(`http://${endpoints.dependencies.backend.address.host}` +
      `:${endpoints.dependencies.backend.address.port}/health`);

5. Commander commands

portreeve stacks resolve <activation-id> --component website --json

portreeve stacks snapshot <activation-id> \
  --component website \
  --gateway-host host.docker.internal \
  --file .portreeve/runtime/endpoints.json

The result is useful inside a sandbox but intentionally powerless. It can tell code where to connect; it cannot allocate, reclaim, confirm, stop, or inspect anything through Portreeve.

Check your understanding

Open each question to compare your answer.

1. Why does resolution start from an activation ID?

It structurally selects exactly one immutable generation and prevents mixing addresses from different startup attempts.

2. Is the Docker-network address proof that a container is running?

No. It is a definition-derived service name and container port. Fresh Docker ownership evidence belongs to P5.

3. Why does the launcher supply the sandbox gateway?

The launcher owns sandbox and Docker topology. Portreeve validates the token but does not pretend to discover or verify that network.

4. What lets a consumer detect a stale snapshot?

The document carries revision, generation, activation, and component identity, and the reader can require expected values for all four.

5. What authority does the sandbox document grant?

None beyond read-only addresses. It contains no daemon socket, lease token, process evidence, or mutation operation.
