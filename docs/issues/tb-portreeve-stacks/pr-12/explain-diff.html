01 · Background

What Portreeve coordinates

A development stack is a set of components—perhaps a website, API, and worker— that need stable local TCP endpoints. Portreeve stores the definition, prepares one immutable port generation, leases those ports while a launcher starts the components, and confirms the result using fresh listener or Docker evidence.

Definition

The intended components, endpoints, dependencies, and allocation preferences.

Generation

One immutable assignment of ports for every endpoint in that definition revision.

Activation

The evidence-backed attempt to run components against exactly one generation.

Earlier slices exposed these operations through the Unix-socket protocol, official JavaScript client, and Commander CLI. The desktop already managed the Portreeve daemon and showed port inventory. It did not yet have an authoritative way to ask, “What is the current state of this stack?”

The authority boundary: Portreeve coordinates ports and checks evidence. A project launcher—such as an existing orchestration CLI—still starts and stops the website, API, workers, and containers.
Renderer: reduced view models and named user actions
Preload: a narrow, validated capability allowlist
Main process: serialization, native file picker, official client
Portreeve server: durable state and fresh evidence authority

03 · Code

How the change is assembled

1. One aggregate, read-only status operation

The existing list response describes definitions, but audit history is not a current-state index. The new status operation reads the latest related generation and activation, expires pending leases, and invokes the existing provider evaluator when confirmed endpoints exist. 

POST /v1/stacks/{stackId}/status

{
  "version": 1,
  "status": {
    "stack": { "...": "canonical definition" },
    "generation": { "...": "latest immutable port plan" },
    "activation": { "...": "latest attempt" },
    "providers": [{ "status": "active", "reason": "verified" }]
  }
}

Strict protocol schemas, the official client, TypeScript declarations, and the stacks status CLI all share this shape. stacks show remains definition-only, so an existing command is not silently redefined.

2. A desktop-only adapter over public contracts

stack-adapter.js calls the official client for list, status, resolution, apply, prepare, reconcile, end, prune, and snapshot operations. The native file picker belongs to the main process. Only the definition's parsed content is sent to the client; only a basename reaches the renderer.

The desktop does not import server storage, SQLite, Docker, or shell execution. This keeps “desktop support” from becoming a privileged parallel implementation of Portreeve.

3. Serialized evidence and mutations

The coordinator polls lifecycle, inventory, and stack evidence together. It coalesces overlapping refreshes, waits for a refresh before starting a mutation, rejects concurrent mutations, and collects fresh evidence after each action. On refresh failure it retains the last successful model while recording which source is stale.

4. Reduced schemas and narrow IPC

Shared Zod schemas define everything the renderer may receive or request. The preload exposes named methods rather than raw IPC. Main-process handlers accept only the primary local renderer frame and validate every argument and result. Claims, lease tokens, run IDs, credentials, full stack worktree paths, generic shell execution, and raw socket access do not cross the boundary.

5. The Stacks view

The renderer adds a third tab with stack state, revision, components, endpoints, dependency aliases, host and Docker-network addresses, activation placement, and provider evidence. It offers only Portreeve coordination operations:

  • apply a definition selected through the native file picker;
  • prepare or reuse a complete generation;
  • reconcile current process and Docker evidence;
  • end an activation only through the server's fresh-evidence gate;
  • preview and copy component-scoped discovery JSON;
  • preview old missing-worktree candidates and type PRUNE before deletion.

The five-second poll no longer rebuilds an unchanged stack panel. This preserves open component disclosures, keyboard focus, and a gateway host being edited. Copy actions use one bounded main-process clipboard capability because the desktop's Chromium permission policy intentionally denies renderer clipboard access.

04 · Safety

Failures remain informative without broadening authority

The original GUI collapsed a useful lifecycle failure into install: failed (internal). This slice carries trusted structured error codes and messages into the last-operation panel. Errors without that contract are generalized instead of echoing arbitrary internals.

Fresh evidence

Stack mutations are withheld when stack collection fails, and the server revalidates every action.

Explicit consent

Ending explains that no provider is stopped. Pruning requires preview plus the exact word PRUNE.

Least privilege

The renderer receives named capabilities, not a shell, filesystem API, socket, Docker API, or database handle.

Deliberate non-feature: no “Start stack” button exists. A project launcher consumes Portreeve's leases and discovery data and remains responsible for application lifecycle and health.
