Portreeve · Pull Request #8

One plan, one startup attempt

This change turns a stack definition into an immutable allocation generation, then gives a launcher a short-lived, all-or-nothing activation protocol. It is coordination without orchestration: Portreeve assigns and verifies ports, while the project launcher still starts and stops its own services.

1 · Background

Ports are relationships, not merely numbers

A single web service can ask Portreeve for an available port and then bind it. A local stack has a harder problem. The API, website, metrics endpoint, and workers must all agree on one coherent set of addresses. If each component asks independently, the launcher can observe a mixture of old and new choices.

PR #7 introduced the durable vocabulary: a stack belongs to a canonical Git worktree; components publish named endpoints; definitions have content-addressed revisions; and each published endpoint links to an ordinary Portreeve claim. This PR adds the runtime half of that model.

Definition

What the stack declares

Components, endpoints, requiredness, dependencies, and exact or preferred port policy.

Generation

One immutable port plan

A complete snapshot tying one definition revision to concrete host ports.

Activation

One startup attempt

Renewable leases and endpoint outcomes for a launcher trying to realize that generation.

Run

Confirmed ownership

A provider that bound a port and proved current listener and process-lineage evidence.

What Portreeve still does not do It does not launch Node, run Docker Compose, order application startup, check HTTP health, or stop providers. The caller remains the orchestrator.
2 · Intuition

Separate planning from the attempt to use the plan

Imagine a stack with api.http and optional api.metrics. Preparation might produce ports 43100 and 43101. That mapping is the generation. It can be handed to every launcher step before any provider starts, so all consumers derive configuration from the same source.

Why two durable objects?

A generation describes a reusable plan. An activation describes a fallible attempt. If the API fails during startup, the attempt may fail while its plan remains valid. A new attempt can reuse the generation instead of silently reallocating every consumer address.

Portreeve
Chooses a complete generation; issues a batch of expiring lease credentials; confirms listener ownership; records outcomes.
Launcher
Distributes the generation; starts providers; renews during slow startup; submits evidence; stops providers before ending.
Provider
Binds only its assigned port. Its live socket and process instance—not a stored PID—become the ownership evidence.

Atomicity is the important property

Beginning does not return “most of” a stack. Every selected endpoint lease is created in one immediate SQLite transaction, or none is. Likewise, only one activation may be live for a canonical worktree. Concurrent callers converge on one generation and only one startup attempt wins.

3 · Code walkthrough

From SQLite invariants to portable public surfaces

1. Storage makes the states durable

Migration 4 adds generation, generation-endpoint, activation, and activation-endpoint tables. Foreign keys preserve the definition revision and claim relationships. Unique constraints prevent duplicate endpoint or port membership inside a generation, and a partial index prevents a second live activation for one stack.

Object Durable facts Important invariant
Generation stack, revision, state, endpoint port snapshot Immutable after creation
Activation generation, aggregate state, timestamps One live attempt
Activation endpoint claim, port, requiredness, lease/run, outcome One outcome per endpoint

2. Preparation reconciles durable intent with live evidence

StackCoordinationService.prepare first attempts to reuse the latest valid generation. Reuse requires the claim assignment still to match and any listener to be freshly verified as that claim's current run. Otherwise the old generation becomes stale and a complete new candidate set is built. 

candidate order = sticky assignment → preferred port → configured ranges
remove          = excluded ports + platform ephemeral range
reject          = another assignment + pending lease + unexplained listener
exact conflict  = fail the whole preparation; never fall back

3. Begin converts the snapshot into short-lived authority

Begin rechecks current listeners, definition revision, endpoint selections, pending work, and worktree exclusivity. It then creates a pending lease for each non-skipped endpoint in one transaction. Tokens are returned only in the begin response; ordinary activation inspection is token-free.

4. Endpoint outcomes drive the aggregate state

startingconfirmeddegradedfailedended

Required endpoints must confirm. An abandoned or expired required endpoint fails the whole activation and transactionally abandons its remaining pending leases. Once required endpoints confirm, a skipped or failed optional endpoint makes the activation degraded. Every automatic transition and lease/run transition is also written to the ordinary history ledger.

5. The same contract reaches every non-desktop surface

A separate stack-activations-v1 capability gates the HTTP/JSON Unix socket routes. The official JavaScript client preflights capability, the declarations describe every response, and Commander exposes prepare, begin, inspect, renew, confirm, abandon, skip, and end. JSON endpoint references are available when canonical names themselves contain dots.

4 · Safety model

Fresh listeners outrank stale bookkeeping

PIDs are recorded as part of a confirmed run, but a stored PID alone never authorizes reuse, confirmation, or cleanup. Portreeve asks the operating system for the current listener, verifies the process instance and lineage, and treats unexplained occupancy as a conflict.

Safe reuse

No listener, or verified same claim

A valid generation can remain the shared port plan.

Stale plan

Unexplained current listener

The generation is invalidated; Portreeve does not kill or adopt the process.

Safe end

All providers already stopped

Portreeve releases records only after fresh evidence shows no confirmed listener.

Known race boundary Listener inspection and the following database transaction are separate system calls. A process can bind between them. This cannot grant false confirmation: provider bind and fresh confirmation remain the final authority. Recovery and reconciliation are expanded in a later slice.
