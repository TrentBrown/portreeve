Trust the CLI as a CLI

This correction removes one false question from Apple evidence—“does Gatekeeper consider this bare executable an app?”—and replaces it with a direct, fail-closed test of the thing users actually receive: the exact signed CLI, quarantined and executed at the exact release version.

Background

The beginner's map

A macOS release has several nested delivery surfaces. PortReeve ships a standalone command-line executable and separate ARM64 and Intel DMGs. Each DMG contains an application, and that application embeds the same architecture's CLI under Contents/Helpers.

Apple's tools answer different questions. codesign reports who signed code, the Team ID, hardened runtime, and timestamp. notarytool and stapler establish Apple's notarization decision and attach it to the DMG. spctl applies Gatekeeper policy to application-like delivery surfaces.

The observed defect. Preview.9's exact signed CLI was valid code, but spctl --type execute rejected it because it “does not seem to be an app.” Both DMGs passed Gatekeeper; the mounted app passed; its embedded helper matched the standalone CLI byte-for-byte; and a quarantined CLI copy ran successfully.

The narrow contract

GateReeve already assesses its app and DMG with Gatekeeper, not a bare CLI. The approved PortReeve amendment adopts that same boundary without changing PortReeve's separate-DMG topology. Historical preview.9 evidence remains immutable; preview.10 must prove the corrected contract from reviewed main.

Intuition

Before

The collector asked an application-policy tool to accept three things: CLI, app, and DMG. The CLI failed because it was the wrong category, even though its signature and behavior were valid.

After

The collector asks each tool a question it can answer truthfully: codesign for every surface, Gatekeeper for app and DMG, and quarantine-plus-execution for the standalone CLI.

A toy example

releaseVersion = "0.1.0-preview.10"
signedCli.sha256 = "abc123…"

1. Copy those exact bytes to a private temporary directory.
2. Write com.apple.quarantine to the copy.
3. Read the attribute back and require the exact value.
4. Execute the copy with --version.
5. Require exactly "0.1.0-preview.10".
6. Remove the temporary directory, success or failure.

This does not weaken trust. It removes an invalid classification check while retaining identity, timestamp, runtime, byte equality, native lifecycle, and create-once evidence. The new check also fails on a missing attribute, failed execution, wrong version, or timeout.

Code walkthrough

1. Collect evidence by surface

collectAppleNativeTrustEvidence no longer calls inspectGatekeeper on cliPath. It still inspects CLI codesign, DMG codesign/Gatekeeper/staple, native lifecycle behavior, the mounted application's exact helper and seal, app codesign/Gatekeeper, and app smoke. The quarantine probe runs before evidence construction.

2. Make schema assertions precise

The assertion loop still requires the expected Developer ID, Team ID, and secure timestamp for CLI, app, and DMG. A separate loop requires accepted Notarized Developer ID Gatekeeper facts only for app and DMG. quarantinedCliSmoke joins the required immutable check list.

3. Probe an exact quarantined copy

verifyQuarantinedNativeCli creates a private temporary directory, copies the already identity-checked CLI, restores executable mode, round-trips one deterministic quarantine value, runs --version, and cleans up in finally. External commands use the existing bounded runner.

4. Test the category boundary

The tests explicitly assert that no spctl command occurs, exactly two xattr calls occur, and the final command asks the probe for its version. A second test demonstrates fail-closed behavior when preview.9 bytes claim to be preview.10.

Deliberately unchanged: two architecture-specific DMGs, exact embedded-helper equality, native ARM64 and Intel evidence, main-only protected signing, separate publication approval, and optional physical-machine installation.
