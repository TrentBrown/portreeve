One signed CLI, preserved all the way into the DMG

This slice builds the protected Apple artifact producer. It does not publish a release and it does not claim the later independent ARM64/Intel verification has happened.

The central idea

Qualified unsigned CLI→ Developer ID signing, once→ Contents/Helpers→ Signed app→ Notarized DMG

At each boundary, PortReeve compares the helper's byte count, SHA-256, and parsed signing facts. Electron may seal the enclosing app, but it must not rewrite the authoritative helper.

What changed

Canonical topology

The executable moved from Contents/Resources to a flat Contents/Helpers entry. Runtime resolution and tests now enforce that contract.

Credential-free qualification

Four native candidates must pass before any Apple secret can be decoded. Qualification explicitly records credentialAccess: false.

Protected producer

One Apple Silicon job signs both macOS architectures, builds both apps and DMGs, notarizes and staples them, and stages one intentional output tree.

Authority separation

The trust job has read-only repository access and Apple credentials only. It has neither publication credentials nor a publication step.

Failure boundaries

Before credential access

Reject the wrong ref, wrong source commit, unsigned public policy, incomplete stage sequence, invalid product identity, or incomplete four-target qualification.

During protected work

Every Apple command is bounded. Signature, team, runtime, timestamp, notarization request, staple, Gatekeeper, or byte mismatch stops production.

During cleanup

The captured keychain search list is restored and the ephemeral keychain and private files are removed after success, preparation failure, action failure, or combined action-and-cleanup failure.

Evidence and limits

  • 62 focused tests and 415 expectations passed with the repository-pinned Bun version.
  • A real x64 app and DMG were built, deep-verified, mounted, and checked for helper equality.
  • No Apple credentials were used from the topic branch; the live protected rehearsal is deliberately main-only.
  • Independent native ARM64 and Intel evidence is P5, in the next slice.
  • Five broad-suite failures in unchanged launcher/MCP/CLI paths are preserved in the verification report with exit status 1.
