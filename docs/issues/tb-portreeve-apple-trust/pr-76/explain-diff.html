Verify native Apple trust, then seal the exact distribution

This slice connects protected artifact production to independent ARM64 and Intel verification, exact distribution metadata, and a tamper-evident publication plan. It still does not publish a release.

Background

Signing changes the bytes of each macOS CLI. That means the unsigned candidate's manifest, formula, checksums, and release record cannot remain authoritative after Developer ID signing. Separately, a producer saying “I made a trusted artifact” is not enough: the exact output must run and pass Apple inspection on both native architectures before final metadata can be trusted.

Intuition

Protected producer

The core rule is simple: every later step consumes the exact bytes and facts established by the previous step. No verifier repairs artifacts, no finalizer guesses trust, and no publisher rebuilds.

Code

Metadata authority

rewriteTrustedReleaseMetadata updates the macOS entries in the manifest and formula, regenerates SHA256SUMS, and synchronizes the release record before upload.

Native collectors

Each architecture checks its standalone CLI, DMG, mounted app, embedded helper, CodeResources seal, signing identity, Team ID, timestamp, Gatekeeper result, staple, and smoke behavior.

Strict aggregation

Exactly one current ARM64 and one current Intel document are accepted. Stale, duplicate, translated, synthetic, cross-architecture, or inconsistent documents fail.

Sealed distribution

Final checksums, formula, cask, update metadata, release assets, and publication plan are derived from final bytes. A separate SHA-256 file makes plan replacement detectable.

Failure boundaries

Corrected during review

The first boundary attempt incorrectly required hardened runtime on the DMG itself. The corrected validator requires hardened runtime on executable CLI and application code, while retaining strict DMG identity, signing, timestamp, Gatekeeper, notarization, and staple checks.

Before finalization

Any missing architecture, identity mismatch, stale source, translated Intel claim, helper mismatch, seal mismatch, Apple assessment failure, or smoke failure stops aggregation and therefore stops finalization.

Before publication

The publisher must receive separate approval, recompute the plan, match the sealed digest, and pass adapter preflight. It cannot access Apple private material, rebuild, re-sign, or infer approval from the trust job.

Evidence and limits

  • 64 focused tests and 495 expectations pass at the corrected source.
  • Typecheck, workflow-document validators, and diff hygiene pass.
  • Trust, native verification, finalization, and publication authorities are separated in workflow source.
  • The actual protected ARM64 and Intel run is P8 from reviewed main.
  • The repository-wide check retains exit 1 for five unchanged local launcher/MCP/CLI failures.
  • No publication action is part of this slice or its forthcoming rehearsal.
