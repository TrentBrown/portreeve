Background

A macOS release has several independent claims. Developer ID signing identifies the producer. Hardened runtime and secure timestamps constrain and preserve the signature. Apple notarization scans a submitted package. Stapling attaches Apple's ticket to the DMG. Gatekeeper then assesses the user-facing app and disk image. None of these facts, by itself, proves that the command-line executable inside the app is the same file offered as a standalone download.

Key distinction. Trust approval is permission to create signed artifacts. Publication approval is permission to change public distribution surfaces. PortReeve keeps them in separate protected environments.

The implementation therefore builds once, transforms the two macOS CLIs under one protected producer, packages separate ARM64 and x64 DMGs, and asks native machines to verify the exact output. A sealed release record is the authority; filenames are only labels.

Intuition

Think of the candidate as a chain of custody. Each box consumes bytes whose digest was fixed by the previous box. A box may add evidence, but it may not silently rebuild or substitute the payload.
