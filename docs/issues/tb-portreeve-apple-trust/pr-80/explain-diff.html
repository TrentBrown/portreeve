Make Apple trust finalization atomic

This correction addresses the preview.8 failure after Apple had accepted both architecture-specific DMGs. It makes trusted metadata a single authoritative transformation, preserves recovery material until evidence is durable, and prevents GitHub job reruns from creating another protected attempt.

1. Background

The protected producer starts from a credential-free, qualified release record. Inside one short-lived Apple credential scope it signs both macOS CLIs, packages and signs both desktop applications, creates architecture-specific DMGs, submits each exact DMG to Apple, waits for acceptance, staples the ticket, and produces a trusted release workspace.

For 0.1.0-preview.8, Apple accepted four submissions: ARM64 and x64 in the original workflow attempt, then both architectures again after GitHub’s “Re-run jobs” action. Both workflow attempts subsequently failed with Trusted manifest predecessor identity is invalid.

The cause: the producer copied an already-signed manifest into the output and then asked the authoritative rewrite to find the original unsigned predecessor identities. Those identities were no longer present, so its safety check correctly rejected the workspace.

The public GitHub release and Homebrew state did not change. The preview identifier is treated as consumed because protected production occurred and the recovery uploads did not retain the submitted DMG bytes.

2. Intuition

Corrected ordering

Qualified setuntouched source
Copy oncepredecessor manifest
Overlay bytessigned CLIs + DMGs
Rewrite onceall identities agree
Durable evidencethen delete candidates

The key invariant is simple: the metadata rewrite must receive exactly the predecessor identities in the qualified set and must be the only operation that changes those identities to the signed values.

3. Code walkthrough

A. Reject protected reruns up front

GITHUB_RUN_ATTEMPT now joins the protected-context proof. Any defined value other than 1 is rejected before credential setup and before any Apple submission.

+ const githubRunAttempt = options.githubRunAttempt ?? process.env.GITHUB_RUN_ATTEMPT;
...
+ if (context.githubRunAttempt !== undefined && context.githubRunAttempt !== '1') {
+   throw new Error(
+     'Apple trusted-artifact production cannot be rerun after a protected attempt; dispatch the next unused preview version.',
+   );
+ }

B. Centralize staging and metadata transformation

The new exported stageTrustedReleaseArtifacts function owns the entire transition from qualified bytes to a trusted staging workspace:

C. Retain recovery candidates to the durable boundary

Exact request-bound DMG candidates are no longer removed immediately after copying artifacts. Cleanup moves past release record, release state, Apple evidence, and producer evidence persistence. If a failure occurs earlier, the outer recovery path can still upload the exact submitted bytes.

Recovery rule: an Apple request ID is meaningful only when it remains bound to the exact bytes submitted. A filename or regenerated DMG is not enough.

D. Align operator guidance

The release runbook and repository-owned release skill now say not to use GitHub Actions “Re-run jobs” once protected production has begun. The ordinary recovery is to preserve evidence and dispatch the next unused preview version. Exact-byte recovery remains available only where the retained candidate and request history support it.
