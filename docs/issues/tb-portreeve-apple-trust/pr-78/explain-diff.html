What happened

Apple notarized preview .6
spctl accepted it
Output named the assessed path
Parser expected a bare word

The real command emitted:

/tmp/PortReeve-0.1.0-preview.6-macos-arm64.dmg: accepted
source=Notarized Developer ID
origin=Developer ID Application: Trent Brown (PMWYD5A82A)

The code change

- !/^accepted$/mu.test(output)
+ !/^(?:.+: )?accepted$/mu.test(output)

The optional prefix is restricted to the same complete line and must end in : accepted. The existing bare form remains valid for deterministic fixtures.

What remains mandatory

  • the command exits with status zero;
  • the status line is exactly bare or path-prefixed accepted;
  • the source is exactly Notarized Developer ID;
  • the origin is exactly PortReeve's expected Developer ID identity.

A path-prefixed rejected status has an explicit regression test and still throws.
