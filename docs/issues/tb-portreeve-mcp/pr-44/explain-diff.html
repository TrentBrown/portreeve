PR #44 · MCP slice I-2

A real stdio bridge,
without a second authority.

PortReeve can now be launched by an MCP host, speak both current stateless and maintained legacy protocol eras, and expose safe global inspection while the one daemon remains the only owner of durable port state.

The central boundary

MCP host→ stdio → PortReeve bridge→ calls → Official JS client→ Unix HTTP/JSON → Single daemon

The new portreeve mcp serve command is an adapter, not a second server of record. It opens no network listener, reads no SQLite file, and does not shell through other CLI commands. Its stdout belongs exclusively to MCP framing; diagnostics go to stderr.

Two protocol eras

Official SDK v2 accepts legacy initialize as well as the 2026-07-28 stateless server/discover envelope.

Fifteen focused reads

Health, compatibility, diagnostics, settings, ports, claims, stacks, generations, activations, and structured history.

Bounded by construction

Collections return 50 records by default, accept at most 200, and continue through opaque non-authoritative cursors.

Recoverable absence

The bridge stays alive when the daemon is missing or incompatible and retries the socket on every later domain call.

What an agent sees

{
  "ok": false,
  "error": {
    "code": "portreeve_unavailable",
    "message": "PortReeve is unavailable …",
    "retryable": true,
    "details": { "socketPath": "…" }
  }
}

Expected daemon failures are structured tool results, not process crashes. Diagnostics remain successful and include actionable instructions to start or update PortReeve. Unknown internal exceptions are reduced to a stable generic message rather than leaking arbitrary exception text.

Deliberately not in this slice

No credential-bearing operations or mutations are registered yet. The vault and ordinary coordination lifecycle arrive in I-3; evidence-bound consequential actions arrive in I-4; remaining catalog families and the final completeness audit arrive in I-5. MCP resources, prompts, subscriptions, HTTP transport, server lifecycle control, unsafe eviction, arbitrary shell/filesystem access, and raw output remain excluded.
