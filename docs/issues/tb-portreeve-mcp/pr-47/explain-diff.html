Launcher coordination, not launcher execution

MCP host
Names stack, action, caller operation, and exact launcher revision.
→
stdio bridge
Calls the official client and hides the returned credential.
→
PortReeve daemon
Admits and records one renewable operation.
↔
Project launcher
Independently runs the developer's actual command.
The security boundary: the bridge never receives a shell command from the model. The project launcher performs work through its existing integration; MCP only coordinates durable identity, deadlines, evidence summaries, and outcomes.

The launcher credential stays backstage

daemon begin → raw launcher credential
               ↓ process-local only
bridge vault → random 43-character handle → MCP result
               ↓ auto renew at min(TTL / 3, 10 seconds)
complete / 10-minute expiry / bridge exit → erase credential

An explicit renew can extend total custody, but never beyond sixty minutes from acquisition. Another bridge has a different vault and cannot use the handle. Safe begin and completion replay are stored separately from the credential, so retries do not justify retaining secret authority.

Check your understanding

1. Does launcher begin run npm run dev?
No. It admits a coordination record and holds its credential. The developer's separate project launcher runs the command.
2. Why return a credential handle?
The model needs a reference for later renew or complete calls, but it never needs the raw secret. The random handle is meaningful only inside its originating bridge.
3. Does the snapshot tool write PORTREEVE_ENDPOINTS_FILE?
No. MCP receives a typed in-memory snapshot. A trusted launcher may decide how to inject or persist it outside this bridge.
4. What makes begin and complete retries safe?
Begin uses explicit caller identity plus bridge-local replay while custody is live. Completion stores only its achieved safe result after erasing the credential.
5. What remains after this PR?
I-6 adds CLI/Desktop setup generation. I-7 runs the final packaged host, platform, Docker, concurrency, leakage, and evidence-change matrix.
