Background

PortReeve has one durable daemon per operating-system user. An MCP host does not connect to that Unix-socket HTTP API directly. Instead, the host starts a small stdio bridge from the existing PortReeve executable. The bridge translates MCP tool calls into official JavaScript-client calls against the daemon.

Before this PR, the bridge and all 51 tools existed, but the user still had to know each host’s configuration syntax and discover a reliable executable path. GUI hosts make the latter surprisingly important: they often do not inherit the same PATH as an interactive shell.

The governing safety constraint: setup should explain and generate. It must not edit Codex, Claude, or generic host settings, launch an agent host, or turn the renderer into a filesystem or executable-path authority.

Intuition

All host formats describe the same process. Only the envelope changes.

command: /Users/alex/Library/Application Support/Portreeve/bin/portreeve
args:    mcp serve --label codex

Exact mode

Uses the stable managed installation. It is machine-specific but reliable even when a GUI host has a restricted PATH. This is the default.

Portable mode

Uses bare portreeve. The snippet travels more easily, but the host environment must arrange PATH correctly. This choice is explicit.

The optional label is equally modest. It helps logs distinguish, for example, codex-worktree-4 from claude-local. It cannot select a worktree, claim a port, identify a stack, or grant permission.

Code walkthrough

1. One pure setup generator

src/mcp/setup.js validates a closed request consisting of host, portable mode, and optional label. A trusted caller separately supplies the exact path. The module returns a strict result containing the canonical command vector, rendered configuration, optional registration command, and explanatory notes.

Generic hosts receive a stdio JSON descriptor. Codex receives TOML plus codex mcp add. Claude Code receives an mcpServers JSON object plus claude mcp add --scope user. JSON and TOML strings use native escaping; terminal instructions quote the path as one POSIX shell word.

2. A local CLI generation command

portreeve mcp setup --host codex
portreeve mcp setup --host claude-code --portable
portreeve mcp setup --host generic --label my-agent --json

The command resolves the managed path with PortReeve’s existing platform-path policy, invokes the pure generator, and renders either copyable text or the standard versioned JSON envelope. It does not construct a daemon client.

3. Main-process authority, narrow IPC

The Electron main process constructs a setup adapter with the managed path. IPC accepts only the three renderer choices, parses the generated result, and returns safe data. The preload independently checks every output field before exposing it to the page. The renderer never sends a path.

4. Documentation and tests

The public MCP and CLI guides now explain both variants and the per-host-bridge/single-daemon topology. Tests cover all formats, CLI output, compiled inclusion, unknown-field rejection, path injection refusal, strict IPC/preload shape, Desktop controls, Guide linking, and the absence of third-party writes.
