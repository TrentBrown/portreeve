Finding the stack you are already inside

Background

Ports belong to a runnable stack, not necessarily a repository

Portreeve stores a stack definition and allocates its published endpoints. A stack root is the canonical real path of the directory containing one independently runnable stack. That directory may itself be a Git worktree, but it may just as naturally contain a frontend repository, a backend repository, and a worker repository.

/customer-stack — stack root and portreeve.stack.json
frontend/.git — child repository
frontend/src/routes — current directory
backend/.git — another child repository

Before this PR, implicit apply looked only for portreeve.stack.json in the current directory. Status likewise treated the current directory itself as the root. Running either command from frontend/src/routes therefore missed the actual stack.

The authority split: the project-owned JSON file is authoritative for topology and apply. Portreeve's database is authoritative for the last registered state and may support status when the file is temporarily missing. The database never silently recreates an apply.

The existing server invariant

PR #14 established that registered stack roots cannot overlap. A registered parent and registered child cannot coexist. This turns status fallback into a simple question: at most one valid registered root can contain the current directory.

Intuition

The CLI now resolves location before it performs the operation. Think of resolution as a small policy layer in front of the existing client.

Explicit file?
Use its parent
→
Explicit root?
Use its standard file
→
Neither?
Walk upward
→
No file?
Apply refuses

Status shares the first part of that reasoning. Its final step differs: when the upward walk finds no file, status lists registered stacks and asks which root contains the current real directory.

Explicit root
Exact selection
→
Enclosing file
Nearest ancestor
→
Registered root
Status-only fallback
→
No match
Exit 10

Git never appears in either algorithm. The current directory and candidate roots are canonical filesystem paths. That is the crucial inversion: repository structure is application content, not Portreeve identity.

Code walkthrough

New policy module

stack-selection.js

selectStackDefinition resolves explicit selectors or delegates to ancestor discovery. findEnclosingStackDefinition starts from the real directory and walks to the filesystem root. selectRegisteredEnclosingStack performs separator-aware containment and rejects impossible overlap.

Command wiring

commands/stacks.js

Apply reads only the selected file and sends the selected root to the existing official client. Status uses one client instance, prefers a file-derived root, then performs the registered-state fallback.

Public surface

program.js

stacks apply gains --stack-root; its --file description becomes explicit. Status help now describes enclosing or explicitly selected behavior.

Evidence

Source and compiled tests

Both integration paths create a non-Git parent, initialize frontend and backend Git repositories, invoke apply from one child, and invoke status from the other. The compiled test removes the definition before status to prove the fallback in the shipped executable.

The ancestor loop

start = realpath(current directory)
repeat:
  candidate = start / "portreeve.stack.json"
  if candidate is a file: return candidate and start
  if candidate exists but is not a file: fail clearly
  if start is the filesystem root: return no match
  start = parent(start)

Why containment is not a prefix test

The string /tmp/customer-stack-copy begins with /tmp/customer-stack, but it is not inside that root. The code uses path.relative and checks path-segment boundaries, so only the root itself or a true descendant matches.

Important cases

Inside a child repository

Implicit apply crosses .git, finds the parent file, and registers the parent real path.

Definition accidentally deleted

Status finds no file, selects the registered enclosing root, and remains useful for diagnosis. Apply fails with exit 50.

Both selectors supplied

The CLI rejects --file plus --stack-root; it does not invent precedence.

Corrupt overlapping records

Status refuses multiple enclosing matches and names the violated invariant rather than making a nondeterministic choice.
