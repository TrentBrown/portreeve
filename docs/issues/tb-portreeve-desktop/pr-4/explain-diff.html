A desktop window with a deliberately narrow waist

This change does not yet make Portreeve a desktop-managed service. It proves the more important prerequisite: a packaged Electron application can observe the existing authority without becoming a second authority, weakening process isolation, or inventing another integration contract.

Background

Portreeve is a per-user service that coordinates development TCP ports. Its durable registry is useful, but the truth about a live listener still comes from operating-system evidence. Before this PR, operators used the CLI and JavaScript client. A desktop interface was planned, but Electron introduces a new security boundary: the page a user sees must not inherit the authority of the Node-powered main process.

CLI contract

portreeve status --json returns layered installation, supervisor, and socket evidence.

Client contract

The official JavaScript client reads global claim and listener inventory through the private socket protocol.

Desktop contract

The renderer receives only a smaller display schema. It never receives the executable path, socket path, command line, or storage handle.

Release boundary: the embedded CLI is a checksummed local 0.1.0 candidate. The UI says “not for distribution.” Signing, notarization, x64 proof, and published-byte identity remain later work.

Intuition: translate evidence; do not pass authority

Imagine the CLI reports a socket path, a process record containing a private command line, and a claim rooted in a long workspace path. The window needs only “socket unhealthy,” listener PID 9191, and the workspace basename. The main process therefore acts like a customs checkpoint: validate the original record, remove privileged fields, validate the reduced record, and only then cross IPC.

Code walkthrough

Trusted side

artifact.js selects one OS/architecture manifest entry and verifies its safe filename and SHA-256.

cli-adapter.js spawns that exact path with no shell, bounded output, and a timeout.

coordinator.js coalesces refreshes and retains last-known layer data when either source fails.

Untrusted side

preload/index.cjs exposes only get, refresh, and subscribe.

renderer.js renders Overview and Ports without Node access or arbitrary IPC.

The local page sees a strict desktop schema, never raw protocol or CLI objects.

1. Establish a local-only Electron boundary

The BrowserWindow enables sandboxing and context isolation while disabling Node, workers with Node, subframe Node, webviews, insecure content, and experimental features. A custom app:// handler serves only real HTML, CSS, and JavaScript files beneath the renderer root. It rejects malformed paths, traversal, and symlink escapes, and attaches a restrictive Content Security Policy.

2. Use the existing public seams

Lifecycle status comes from the exact embedded executable. Inventory comes from PortreeveClient. Static tests guard against accidental imports from server/storage layers and against generic shells or PATH lookup. This is important architecturally: the desktop remains a consumer of Portreeve rather than a privileged fork of it.

3. Serialize freshness

A single in-flight promise coalesces simultaneous refresh requests. The coordinator polls every five seconds only while the window is visible, stops on hide or minimize, and refreshes on focus or restore. If one source fails, its last successful evidence remains on screen, visibly marked stale beside a current redacted error.

4. Package the proof without claiming a release

The packaging script detects physical Mac architecture, bundles the main process, copies the renderer and preload, and adds the exact checksummed CLI as a resource. The resulting ARM64 app is unsigned engineering evidence. This separation lets UI and security work continue while npm's first publication remains deferred.

Safety edges proved by the slice

No race between refreshes

Focus, polling, and a manual refresh share the same in-flight promise.

No stale PID authority

PIDs are displayed evidence only. The desktop does not mutate or kill processes in this slice.

No secret echo

Adapter parse failures use fixed messages, and coordinator errors redact upstream message text.

No arbitrary navigation

New windows and webviews are denied; navigation is pinned to the one local renderer URL.

No provisional release claim

The candidate's origin and checksum are shown, alongside an explicit non-distribution label.

No hidden background polling

Hide and minimize stop the timer; focus and restore collect fresh evidence.
