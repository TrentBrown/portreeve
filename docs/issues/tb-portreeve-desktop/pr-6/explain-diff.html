Update discovery with deliberately little authority

The desktop can now tell a developer that a newer release exists, but the network response cannot choose where to navigate, download code, install anything, or interfere with local Portreeve management.

Background

Earlier slices established the desktop's local authority boundary: lifecycle operations go through the exact bundled CLI, inventory goes through the public JavaScript client, and the renderer sees only reduced state. P8 adds one remote concern—whether a newer desktop version exists—without weakening those boundaries.

One inputA strict JSON manifest containing only schema version and latest desktop version.
One cadenceEvery attempt, including a failure, suppresses another check for 24 hours.
One navigationThe compiled GitHub Releases page; neither manifest nor renderer supplies a URL.
Zero mutationNo download, install, restart, service upgrade, or automatic desktop replacement.

The intuition

Treat update discovery as an untrusted hint, not an updater. Its only useful statement is “version X appears newer than this desktop.” The main process validates that hint, stores a small reduced result, and lets the renderer present it. Every higher-authority action remains a separate human choice outside the response's control.

1
Local state first. Lifecycle and port evidence refreshes and renders before any remote check begins.
2
Read the private cache. A valid result younger than 24 hours means no request at all.
3
Fetch one fixed resource. The request has no query, body, credentials, referrer, installation ID, or project data.
4
Bound and validate. Five-second timeout, redirect refusal, streamed 16 KiB limit, JSON parse, strict schema, and SemVer comparison.
5
Reduce every outcome. The renderer sees only not-checked, current, available, or unavailable plus timestamp/version.

What changed in code

Main-process update adapter

apps/desktop/main/update.js owns remote access, the private cache, version comparison, and external navigation. Overlapping callers share one active promise, and cache write failure does not turn a valid check into an application failure. 

GET https://raw.githubusercontent.com/TrentBrown/portreeve/main/distribution/desktop-update.json

credentials: omit
redirect: error
referrer: none
timeout: 5 seconds
maximum body: 16 KiB, enforced while streaming

Independent coordinator publication

The initial coordinator.refresh() remains purely local. Only after it completes does startup fire checkForUpdates() without awaiting it. When discovery settles, the coordinator swaps only the snapshot's update field and publishes again. A failed update cannot label lifecycle or inventory evidence stale.

Strict IPC and presentation

Shared schemas define the manifest and four-state reduced result. The preload exposes one named method with no arguments. Main IPC accepts it only from the trusted main frame, rejects additional arguments, and delegates to a coordinator that refuses unless current state is available.

Public contract

distribution/desktop-update.json is the versioned source consumed from main. docs/desktop-updates.md records that release automation may advance it only after the matching signed and notarized desktop artifacts are actually on the Releases page.

Safety review

Resolved review finding. The first implementation read the complete body before checking its size. Commit 5a5fba2 now counts bytes as the stream arrives and cancels immediately after 16 KiB; the test proves later chunks are not buffered.

The response's authority is intentionally tiny. Even a malformed or malicious manifest can produce only unavailable, current, or available. It cannot introduce a URL, provide executable bytes, call the CLI, or cross the generic shell boundary because no such capability exists.

Evidence limitation. Until this PR merges, the fixed raw-main manifest is not present. Packaged inspection therefore proved the offline/unavailable path. Deterministic tests cover current, available, malformed, timeout, oversized, cached, fixed-navigation, and rejected-IPC paths. Check your understanding

1. Why is the download URL not stored in the manifest?

Because the only network-controlled field needed is a version hint. Keeping navigation compile-time fixed prevents remote data from selecting a destination across the Electron privilege boundary.

2. Why cache failures for the same 24 hours as successes?

The contract is at most one outbound attempt per 24 hours, not one successful attempt. Retrying every launch would violate the privacy and cadence policy and create noisy failure behavior.

3. What prevents a slow network from delaying local port management?

Startup awaits the initial local coordinator refresh first, then starts update discovery without awaiting it. The coordinator later publishes only the update field.

4. What was wrong with checking body size after response.text()?

The entire untrusted response had already been buffered, so the nominal limit did not bound memory. The final implementation counts streamed bytes and cancels at the boundary.

5. Does “available” authorize an upgrade?

No. It enables only a no-argument request to open the fixed Releases page. Desktop installation stays manual, and managed-service upgrade remains a separate confirmed P7 lifecycle action.
