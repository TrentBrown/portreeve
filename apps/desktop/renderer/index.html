      How PortReeve fits

      Guide

      PortReeve is the local authority for development TCP ports on your machine. It gives projects, worktrees, processes, containers, and development sandboxes stable network identities without making every project solve port conflicts independently.

      PortReeve coordinates addresses. Project tools coordinate work.

      One PortReeve server runs for the current operating-system user. The desktop application, portreeve CLI, official JavaScript client, and project launchers all communicate with that same authority.

      Architecture

      One authority, project-owned execution

      Ownership is not readiness

      PortReeve can confirm that an endpoint is listening and that the expected process or container owns it. It does not claim that the application is healthy or ready to serve requests.

      Concepts

      How coordination works

      Allocate, bind, and confirm

      A caller identifies the project, workspace, component, and endpoint, then acquires a short-lived lease for a durable assignment. The service binds that port and confirms ownership using fresh evidence. JavaScript services can use withPort() to hide this negotiation.

      Stacks, generations, and activations

      One independently runnable stack belongs to each root. Its components expose named endpoints and declare dependencies in portreeve.stack.json; current port numbers remain in PortReeve. A generation keeps the whole stack on one coherent endpoint plan, and each start attempt receives a new activation.

      Process and Docker evidence

      Fresh lsof listener evidence is live truth for host ports; stored process IDs are context, not authority. Docker confirmation uses running-container state, exact labels, and publication evidence. PortReeve does not stop project processes or containers itself.

      Sandbox discovery and trust boundaries

      Sandboxed code never receives the control socket. A trusted launcher may write an activation-scoped, read-only endpoint snapshot containing only the addresses that consumer needs—not tokens, host paths, process IDs, container IDs, database access, or mutation authority.

      Desktop, CLI, client, and server

      There is one per-user installation and authority, not separate desktop and CLI servers. Desktop, CLI, and the official JavaScript client use the same private HTTP/JSON socket contract; only the server mutates SQLite.

      What PortReeve deliberately does not do

      PortReeve is not a general project-process supervisor, Docker Compose replacement, startup-order engine, secret manager, application health system, reverse proxy, DNS server, or sandbox control plane.
