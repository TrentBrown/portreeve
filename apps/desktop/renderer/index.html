        Guide
        
            
        What is PortReeve?
        
            
        
              PortReeve is the per-user authority for development TCP ports on your
              machine. It gives projects and services stable network addresses, avoids
              conflicts, and verifies which process or container owns each endpoint.
            
        
            
        
              This becomes especially valuable during concurrent agentic development.
              Multiple agents may run independent copies of the same stack from
              different Git worktrees on one machine. Those copies naturally prefer the
              same default ports, so collisions become frequent unless a shared
              authority coordinates their assignments.
            
        
            
        
              The name borrows from the historical portreeve: a civic official
              responsible for administering a port or market borough. In the older term,
              port could mean a market town—not only a seaport. We use it as a
              modern play on words: PortReeve is the local official responsible for
              coordinating your machine's network ports.
            
        
            
        
              PortReeve coordinates addresses.
              Your project tools start, supervise, and evaluate the health of your
                services.
            
        
            
        
              One PortReeve server runs for the current operating-system user. The
              desktop application, portreeve CLI, official JavaScript
              client, and project launchers all communicate with that same authority.
            
        
          
        
        
        

        
        
          
        
            
        Choose a client
        
            
        Four peers, one PortReeve authority
        
            
        
              Choose the surface that belongs in your workflow. Every client uses the
              same per-user daemon and durable port state; none creates a second
              PortReeve authority.

        What project integration adds
        
              
        
                PortReeve's confirmation guarantee is the same wherever the verified
                activation protocol is used; a generated launcher can obtain the same
                ownership proof. Project integration removes the extra adapter boundary:
                the project tooling that owns provider lifecycles also owns lease
                acquisition, binding confirmation, failure handling, and cleanup.
              
        
              
        
                Confirmation proves ownership, not application readiness.
                It succeeds only after fresh listener or Docker evidence shows that the
                expected provider owns the binding. Whether the application can handle a
                real request remains a project-owned health decision.
              
        
            
        
          
        
        
        

        
        
          
        
            
        Architecture
        
            
        
              One authority, project-owned execution
            
        
            
        
              The integration tool changes between Good, Better, and Best. The actors,
              PortReeve concepts, and startup sequence below do not.
            
        
          
        
          

          
          
        
            
        Ownership is not readiness
        
            
        
              PortReeve can confirm that an endpoint is listening and that the expected
              process or container owns it. It does not claim that the application is
              healthy or ready to serve requests.
            
        
          
        
        
        

        
        
          
        
            
        Diagram details
        
            
        Follow the concepts deeper
        
            
        
              These notes expand the sequence and state-model diagrams without adding
              more steps to their first reading.
            
        
          
        
          
        
            Claims, preparation, and leases
            
        
              
        
                Apply links every published endpoint to a durable claim. Prepare uses
                those claims to allocate one complete generation without starting a
                lease deadline. Begin then issues an activation-scoped lease for every
                selected endpoint. For a standalone service, withPort()
                hides the corresponding acquire, bind, and confirm negotiation.
              
        
            
        
          
        
          
        
            Generations, activations, resolve, and confirm
            
        
              
        
                One independently runnable stack belongs to each root. Its components
                expose named endpoints and declare dependencies in
                portreeve.stack.json; current port numbers remain in
                PortReeve. A generation keeps the whole stack on one coherent endpoint
                plan, while each start attempt receives a new activation. Resolve reads
                addresses from that generation; Confirm separately proves that the
                expected process or container actually owns a leased endpoint.
              
        
            
        
          
        
          
        
            Process and Docker evidence
            
        
              
        
                Fresh lsof listener evidence is live truth for host ports;
                stored process IDs are context, not authority. Docker confirmation uses
                running-container state, exact labels, and publication evidence.
                PortReeve does not stop project processes or containers itself.
              
        
            
        
          
        
          
        
            Desktop, CLI, client, and server
            
        
              
        
                There is one per-user installation and authority, not separate desktop
                and CLI servers. Desktop, CLI, and the official JavaScript client use
                the same private HTTP/JSON socket contract; only the server mutates
                SQLite.
              
        
            
        
          
        
          
        
            What PortReeve deliberately does not do
            
        
              
        
                PortReeve is not a general project-process supervisor, Docker Compose
                replacement, startup-order engine, secret manager, application health
                system, reverse proxy, DNS server, or sandbox control plane. It can
                verify ordinary Docker-backed endpoints, but it does not currently
                provide Docker Sandbox orchestration or integration.
